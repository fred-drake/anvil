# pi-anvil Code Review Issues

Full-codebase review performed 2026-07-06. Baseline: `npm run check` passes (typecheck clean, 72/72 tests green), so everything below is a latent defect, hardening gap, or maintainability concern — not a broken build.

## 🔴 High Priority

- [ ] **H1 [SECURITY]** Shell injection via `{input}` templating in deterministic check commands. `renderTemplateString` (`src/prompts.ts:25-27`) substitutes the raw free-form text from `/anvil run <name> <input>` into the command string, which is then executed with `bash -c` (`src/gates.ts:94-99`). A workflow like `command: "test -f {input}"` executes whatever the run input contains (e.g. `foo; rm -rf ~`). The bundled example compounds this: `examples/workflows/demo.ts:23` quotes with `JSON.stringify`, which is JSON escaping, not shell escaping — double quotes still allow `` ` `` and `$(...)` substitution. Fix: shell-escape `{input}`/`{loop}` when rendering into a `command` context (single-quote escaping like `shellEscape` in `src/subagent/cmux.ts:23`), or pass the input via an environment variable (e.g. `ANVIL_INPUT`) instead of string substitution, and fix the demo to use proper quoting.

- [ ] **H2 [BUG]** Per-step model/thinking selection leaks into the user's session after the run ends. The engine only restores defaults lazily at the *start* of the next defaulted step (`src/engine.ts:256`); `finish()` (`src/engine.ts:158-175`) never restores. If the last step sets `model`/`thinkingLevel` — or the run fails or is aborted mid-step — the main session is silently left on that step's model and thinking level (e.g. `feature-forge` would leave the session on `openai-codex/gpt-5.5:high` only if its last step ran in main, and any main-session workflow ending on a model override does this today). Fix: call `applyStepModelSelection(undefined)` in `finish()` (and on abort) so the session always returns to its workflow-start model.

## 🟡 Medium Priority

- [ ] **M1 [BUG]** Concurrent `/anvil run` race can start two overlapping runs. `handleRun` checks `getActiveRun()` first, then `await`s workflow discovery and `ctx.waitForIdle()` before calling `setActiveRun` (`src/index.ts:160-191`). Two `/anvil run` commands issued in quick succession both pass the guard; the second overwrites `activeRun`, `/anvil abort` only reaches the newer run, and both runs interleave `sendUserMessage` calls into one session. Fix: reserve the active-run slot synchronously before the first `await` (set a placeholder and roll it back on early return).

- [ ] **M2 [BUG]** Subagent steps have no timeout. `pollForExit` (`src/subagent/cmux.ts:231-255`) loops forever waiting for the `.exit` sidecar or the terminal sentinel; a wedged child `pi` session (or a sentinel that scrolled away with a lost sidecar) hangs the workflow indefinitely, with `/anvil abort` as the only recovery. Deterministic checks default to a 300s timeout — subagent steps should have an analogous (generous, configurable) `timeoutMs`.

- [ ] **M3 [BUG]** `isAbortError` misclassifies real failures as aborts. `src/engine.ts:501-503` treats any error whose message matches `/aborted|abort/i` as a user abort, so a subagent or provider failure like "request aborted by upstream" ends the run with `state: "aborted"` and a generic `failureReason: "aborted"`, discarding the real message. Fix: use a dedicated error class or sentinel (e.g. `AnvilAbortError`) thrown by `throwIfAborted`/the waiters, and check `options.signal?.aborted` plus `instanceof` instead of message matching.

- [ ] **M4 [PERFORMANCE]** Autocomplete executes and re-transpiles every workflow file on each keystroke. Typing after `/anvil run ` calls `getAnvilCompletions` → `discoverWorkflows` (`src/index.ts:400-423`), which `jiti.import`s every file in both workflow dirs with `moduleCache: false, fsCache: false` (`src/discovery.ts:36-66`). That's arbitrary module code execution plus full TS transpilation per keystroke. Fix: cache discovery results briefly (mtime-based invalidation), and/or list names from filenames without importing until a workflow is actually validated/run.

- [ ] **M5 [PERFORMANCE]** Synchronous subprocess calls block the session's event loop during subagent launches. `createSurface`/`sendLongCommand`/`renameSurface` use `execSync`/`execFileSync`/`spawnSync`, and `restoreFocusIfStolen` blocks the thread for 100ms with `Atomics.wait` (`src/subagent/cmux.ts:103`, `120-195`). While these run, the entire pi UI is frozen. Fix: convert the launch path to the async `execFile` variant already used by `readScreen`, and replace `Atomics.wait` with an async sleep.

- [ ] **M6 [SECURITY]** Harden the shared temp workspace. `runCmuxSubagent` writes task prompts (which can contain sensitive repo context), session transcripts, and a mode-`0o755` launch script under the predictable path `<tmpdir>/pi-anvil/<runId>/` (`src/subagent/runner.ts:95-100`, `src/subagent/cmux.ts:178-184`) with default directory modes. On shared-`/tmp` Linux systems this is readable by other local users and subject to pre-creation of `pi-anvil/`. Fix: create the run directory with `mode: 0o700` (and consider `mkdtemp`), and drop the script mode to `0o600` since it is invoked via `bash <script>`.

- [ ] **M7 [BUG]** `feature-forge` workflow prompts target the wrong project. `.pi/anvil/workflows/feature-forge.ts` tells the agent to use "XCTest targets", "SwiftUI surfaces", and "CLI/GUI parity" (`:40-44`, `:54-58`) while its deterministic gate runs `npm run check && npm test -- --coverage` (`:64`), and the review step appends to `docs/ISSUES.md` (`:81`, `:93`) — a file that doesn't exist (this file is `docs/ISSUE.md`). The prompts look copy-pasted from a Swift project and will misdirect subagents working on this TypeScript repo. Fix: rewrite the step prompts for this repo's conventions and point them at the correct issues file.

- [ ] **M8 [TESTING]** `src/index.ts` contains real logic but is excluded from coverage and largely untested. `resolveModelReference` (provider parsing, ambiguity handling, `src/index.ts:355-372`), `waitForTurnCompletion`/turn-waiter lifecycle (`:460-502`), and the `createEngineHost` wiring (model restore, subagent result injection) have no direct tests; `vitest.config.ts` excludes the whole file from coverage. Fix: extract the pure parts (`resolveModelReference`, arg parsing, waiter logic) into a testable module or add tests against them, and narrow the coverage exclusion.

## 🟢 Low Priority

- [ ] **L1 [DESIGN]** Agent checks are self-graded. The same main agent that performed (or narrated) a step is the one instructed to call `anvil_verdict` on it (`src/prompts.ts:89-108`), so nothing structurally prevents a rubber-stamp `pass: true`; `check.agent` is only a prose hint. Worth documenting the limitation in the README, and longer-term consider running agent checks in a fresh subagent session the way `delegation: { subagent: "cmux" }` steps run.

- [ ] **L2 [BUG]** Cross-session module-global state. `verdictBus` and `turnWaiters` (`src/index.ts:59-60`) and `subagentPane` (`src/subagent/cmux.ts:21`) are module-level singletons. If one process ever hosts multiple sessions, `session_shutdown` clears another session's pending verdicts, and `agent_start`/`agent_end` events resolve the wrong session's waiters. Move this state into the per-extension closure created in `piAnvil(pi)`.

- [ ] **L3 [BUG]** Pane reuse check uses substring matching. `tree.includes(subagentPane)` (`src/subagent/cmux.ts:163-164`) lets `pane:1` match `pane:12`, so a closed pane can be treated as alive and tab creation fails or lands in the wrong pane. Match on a boundary (e.g. regex `\bpane:1\b` or parse the tree output).

- [ ] **L4 [CLEANUP]** Agent-check timeout is dead-configurable. `executeAgentCheck` accepts `timeoutMs` but the engine never passes it (`src/gates.ts:120-124`, `src/engine.ts:435-443`), and `AgentCheck` has no `timeoutMs` field — so 300s is effectively hardcoded while `DeterministicCheck.timeoutMs` exists. Either add `timeoutMs` to `AgentCheck` and thread it through, or drop the parameter.

- [ ] **L5 [BUG]** Timed-out deterministic checks aren't reported as timeouts. `EngineExecResult.killed` is never inspected (`src/gates.ts:100-108`), so a check killed at `timeoutMs` yields a confusing "command exited N" / tail-of-output reason. Include "timed out after Xms" in the reason when `killed` is set.

- [ ] **L6 [VALIDATION]** Duplicate check ids aren't validated, and loop budgets can collide. Loop keys are `<check.id ?? stepId:checkN>-><goto>` (`src/engine.ts:381`); two checks in different steps sharing an `id` and `goto` target silently share one loop budget. Add a duplicate-check-id validation alongside the duplicate-step-id check in `src/validate.ts`.

- [ ] **L7 [UX]** Workflow name collisions are silently last-wins. `discoverWorkflows` dedupes with `byName.set` (`src/discovery.ts:28-33`); project-over-user shadowing is documented, but two same-named files *within* one directory silently drop the alphabetically-earlier one. Surface a warning/`errors` entry on the shadowed entry so `/anvil list` shows the conflict.

- [ ] **L8 [DOCS]** `onFail: "continue"` skips the step's remaining checks. When a check fails with `continue`, the engine advances to the next step immediately (`src/engine.ts:331-337`), so later checks on that step never run. Reasonable behavior, but undocumented — note it in the README/skill docs.

- [ ] **L9 [CLEANUP]** `newRunId` is duplicated verbatim in `src/index.ts:504-506` and `src/engine.ts:493-495`. Export it from one place.

- [ ] **L10 [ROBUSTNESS]** Terminal sentinel can false-match agent output. `pollForExit` falls back to scanning the last 5 screen lines for `__ANVIL_SUBAGENT_DONE_<n>__` (`src/subagent/cmux.ts:18`, `:246`); a subagent that prints that string (e.g. while inspecting pi-anvil itself) is treated as exited. Rare, but a per-launch random nonce in the sentinel would eliminate it.
